# Feature Specification: 首頁與基礎架構

**Feature Branch**: `001-homepage-foundation`
**Created**: 2025-11-17
**Status**: Draft
**Input**: 建立虎山林業官方網站首頁與基礎架構，包含導航列、Hero 區塊、公司簡介、服務項目快速導覽、社群媒體連結、頁尾，支援 RWD 響應式設計

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 快速理解公司業務 (Priority: P1)

企業客戶或政府單位的採購人員透過搜尋引擎找到虎山林業網站，在首頁快速了解公司提供哪些林業服務，並找到聯絡方式進行詢價。

**Why this priority**: 這是網站的核心價值主張。如果訪客無法在短時間內理解公司業務，就會直接離開網站，導致商機流失。符合憲章的「使用者優先」原則。

**Independent Test**: 可透過使用者測試驗證：給予陌生使用者首頁，在 3 秒內能否說出虎山林業的主要業務。

**Acceptance Scenarios**:

1. **Given** 使用者首次訪問網站，**When** 頁面載入完成，**Then** 在視窗第一屏（viewport）即可看到公司名稱、主要業務標語、至少一項核心服務
2. **Given** 使用者瀏覽首頁，**When** 向下捲動查看公司簡介，**Then** 看到「來自台灣各地集結了六位熱愛森林的青年，正在努力推廣台灣林業的發展。Since 2022, From Taiwan」的介紹文字
3. **Given** 使用者想了解服務項目，**When** 在首頁查看服務區塊，**Then** 看到四大服務（森林收穫、原木買賣、森林經營規劃、鏈鋸教育訓練）的卡片式介紹
4. **Given** 使用者對某項服務有興趣，**When** 點擊服務卡片，**Then** 導航至該服務的詳細介紹頁面（未來功能）
5. **Given** 使用者想聯絡公司，**When** 尋找聯絡方式，**Then** 在首頁看到明顯的「立即諮詢」或「聯絡我們」按鈕

### User Story 2 - 跨裝置瀏覽體驗 (Priority: P1)

在山區現場工作的客戶使用手機查看虎山林業網站，能夠流暢瀏覽所有內容，不會出現排版錯亂或需要左右滑動的情況。

**Why this priority**: 林業服務的客戶經常在戶外或山區使用行動裝置。根據憲章的「使用者優先」和「效能優化」原則，RWD 是不可妥協的要求。

**Independent Test**: 在不同裝置（iPhone、Android 手機、iPad、桌機）上測試首頁，確認所有元素正確顯示且可操作。

**Acceptance Scenarios**:

1. **Given** 使用者使用手機訪問網站，**When** 頁面載入，**Then** 所有內容自動適應螢幕寬度，無需左右滑動
2. **Given** 使用者使用平板訪問網站，**When** 查看導航列，**Then** 導航項目排列適合平板螢幕尺寸
3. **Given** 使用者使用桌機訪問網站，**When** 瀏覽首頁，**Then** 內容以多欄佈局呈現，充分利用寬螢幕空間
4. **Given** 使用者使用手機，**When** 點擊導航選單，**Then** 出現響應式的漢堡選單（mobile menu）
5. **Given** 使用者在任何裝置上，**When** 觸碰或點擊按鈕，**Then** 按鈕有明顯的視覺回饋（hover/active 狀態）

### User Story 3 - 社群媒體連結與互動 (Priority: P2)

潛在客戶瀏覽網站後，想要透過社群媒體進一步了解虎山林業的工作實況與最新動態。

**Why this priority**: 虎山林業已經在 Facebook、Instagram、YouTube 累積了內容，社群媒體連結能引導訪客深入了解公司，建立信任感。

**Independent Test**: 點擊社群媒體圖示，確認能正確導向對應的社群平台頁面。

**Acceptance Scenarios**:

1. **Given** 使用者在首頁或頁尾，**When** 看到社群媒體區塊，**Then** 看到 Facebook、Instagram、YouTube 的圖示連結
2. **Given** 使用者點擊 Facebook 圖示，**When** 連結開啟，**Then** 在新分頁打開 https://www.facebook.com/HUSHANForestry/
3. **Given** 使用者點擊 Instagram 圖示，**When** 連結開啟，**Then** 在新分頁打開 https://www.instagram.com/hu_shan_tw/
4. **Given** 使用者點擊 YouTube 圖示，**When** 連結開啟，**Then** 在新分頁打開 https://www.youtube.com/@虎山林業
5. **Given** 使用者使用螢幕閱讀器，**When** 導航至社群媒體圖示，**Then** 聽到明確的標籤說明（例如「前往 Facebook 粉絲專頁」）

### User Story 4 - 網站導航與頁面架構 (Priority: P1)

使用者透過導航列快速訪問網站的各個主要頁面（首頁、關於我們、服務項目、聯絡我們等）。

**Why this priority**: 清晰的導航是網站可用性的基礎，符合「3 次點擊內找到資訊」的憲章要求。

**Independent Test**: 從首頁開始，測試是否能在 3 次點擊內到達任何目標頁面。

**Acceptance Scenarios**:

1. **Given** 使用者在任何頁面，**When** 查看頁面頂部，**Then** 看到固定的導航列，包含：Logo、首頁、關於我們、服務項目、聯絡我們
2. **Given** 使用者點擊 Logo，**When** 在任何頁面，**Then** 返回首頁
3. **Given** 使用者點擊導航項目，**When** 頁面切換，**Then** 當前頁面的導航項目有視覺標示（active 狀態）
4. **Given** 使用者向下捲動頁面，**When** 捲動超過一定距離，**Then** 導航列保持固定在頂部（sticky header）
5. **Given** 使用者使用鍵盤導航，**When** 按 Tab 鍵，**Then** 焦點依序移動至導航項目，並有明顯的焦點標示

---

### User Story 5 - 快速載入與效能 (Priority: P1)

使用者在網路訊號較弱的環境（如山區）訪問網站，頁面仍能在合理時間內載入並可用。

**Why this priority**: 符合憲章的「效能優化（不可妥協）」原則。林業客戶經常在偏遠地區工作，網站必須在低頻寬環境下也能快速載入。

**Independent Test**: 使用 Chrome DevTools 模擬 3G 網路，測試首頁載入時間是否 < 3 秒。

**Acceptance Scenarios**:

1. **Given** 使用者在標準 4G 網路環境，**When** 訪問首頁，**Then** 首次內容繪製 (FCP) < 1.5 秒
2. **Given** 使用者在標準 4G 網路環境，**When** 訪問首頁，**Then** 最大內容繪製 (LCP) < 2.5 秒
3. **Given** 使用者在慢速 3G 網路環境，**When** 訪問首頁，**Then** 頁面在 3 秒內顯示主要內容（文字與佈局）
4. **Given** 圖片資源較大，**When** 頁面載入，**Then** 實作 lazy loading，螢幕外的圖片延遲載入
5. **Given** 使用者測試網站效能，**When** 執行 Lighthouse 測試，**Then** 效能評分 > 90

---

### Edge Cases

- **網路中斷**: 使用者在頁面載入過程中網路中斷，顯示友善的錯誤提示而非空白頁面
- **舊版瀏覽器**: 使用者使用不支援現代 CSS/JS 的舊版瀏覽器（IE11），顯示降級體驗或升級瀏覽器提示
- **極小螢幕**: 使用者使用極小螢幕裝置（< 320px），內容仍保持可讀性
- **超寬螢幕**: 使用者使用超寬螢幕（> 1920px），內容不會過度延伸，保持適當的最大寬度
- **JavaScript 停用**: 使用者停用 JavaScript，網站的基本導航與內容瀏覽功能仍可使用（漸進增強）
- **圖片載入失敗**: 某些圖片無法載入時，顯示適當的 alt 文字與佔位符
- **長文字內容**: 導航項目名稱或按鈕文字過長時，正確處理換行或截斷

## Requirements *(mandatory)*

### Functional Requirements

#### 導航列 (Navigation Bar)
- **FR-001**: 網站必須提供固定在頁面頂部的導航列，包含：Logo、首頁、關於我們、服務項目、聯絡我們
- **FR-002**: 點擊 Logo 必須返回首頁
- **FR-003**: 當前頁面的導航項目必須有視覺標示（active 狀態）
- **FR-004**: 導航列必須在使用者向下捲動時保持固定在頂部（sticky header）
- **FR-005**: 在手機與平板裝置上，導航列必須轉換為漢堡選單（mobile menu）
- **FR-006**: 導航項目必須支援鍵盤導航，焦點狀態有明顯視覺標示

#### Hero 區塊
- **FR-007**: 首頁必須包含 Hero 區塊，展示品牌標語與視覺主圖
- **FR-008**: Hero 區塊必須包含明確的行動呼籲按鈕（CTA），例如「立即諮詢」
- **FR-009**: Hero 區塊的背景圖片必須經過優化，支援 WebP 格式與 responsive images
- **FR-010**: CTA 按鈕必須導向聯絡頁面或詢價表單

#### 公司簡介區塊
- **FR-011**: 首頁必須展示公司簡介文字：「來自台灣各地集結了六位熱愛森林的青年，正在努力推廣台灣林業的發展。Since 2022, From Taiwan」
- **FR-012**: 公司簡介區塊可選包含「了解更多」按鈕，導向「關於我們」頁面

#### 服務項目快速導覽
- **FR-013**: 首頁必須展示四大服務項目的卡片式導覽：森林收穫、原木買賣、森林經營規劃、鏈鋸教育訓練
- **FR-014**: 每個服務卡片必須包含：服務名稱、簡短描述（1-2 句話）、代表性圖示或圖片
- **FR-015**: 服務卡片必須可點擊，導向對應的服務詳細頁面（連結準備，頁面於後續功能開發）
- **FR-016**: 服務卡片在桌機上以多欄佈局呈現，在手機上堆疊為單欄

#### 社群媒體連結
- **FR-017**: 網站必須在首頁與頁尾提供社群媒體連結，包含 Facebook、Instagram、YouTube
- **FR-018**: 社群媒體連結必須在新分頁開啟（`target="_blank"`），並包含 `rel="noopener noreferrer"` 安全屬性
- **FR-019**: 社群媒體圖示必須有適當的 alt 文字或 aria-label，例如「前往 Facebook 粉絲專頁」
- **FR-020**: 社群媒體連結的 URL：
  - Facebook: https://www.facebook.com/HUSHANForestry/
  - Instagram: https://www.instagram.com/hu_shan_tw/
  - YouTube: https://www.youtube.com/@虎山林業

#### 頁尾 (Footer)
- **FR-021**: 網站必須提供頁尾，包含：公司名稱、版權聲明（© 2022-2025 虎山林業）、社群媒體連結
- **FR-022**: 頁尾可選包含：快速連結（導航項目）、聯絡資訊
- **FR-023**: 頁尾文字必須清晰可讀，與背景有足夠的對比度（至少 4.5:1）

#### 響應式設計 (RWD)
- **FR-024**: 網站必須支援以下斷點的響應式設計：
  - Mobile: 320px - 767px
  - Tablet: 768px - 1023px
  - Desktop: 1024px+
- **FR-025**: 在所有裝置上，內容不得需要水平捲動
- **FR-026**: 觸控目標（按鈕、連結）在手機上必須至少 44x44px（符合 WCAG 2.1 AA 標準）
- **FR-027**: 文字大小在手機上必須至少 16px（避免移動瀏覽器自動縮放）

#### SEO 與可訪問性
- **FR-028**: 首頁必須包含適當的 meta tags：
  - `<title>`: 虎山林業 | 台灣專業林業服務 | 森林收穫、原木買賣、經營規劃
  - `<meta name="description">`: 虎山林業由六位熱愛森林的青年於 2022 年創立，提供森林收穫、原木買賣、森林經營規劃、鏈鋸教育訓練等專業林業服務
  - `<meta name="keywords">`: 台灣林業, 森林收穫, 伐木服務, 原木買賣, 森林經營規劃, 鏈鋸訓練
- **FR-029**: 首頁必須使用語義化 HTML 標籤（`<header>`, `<nav>`, `<main>`, `<section>`, `<footer>`）
- **FR-030**: 所有圖片必須包含 alt 文字
- **FR-031**: 頁面必須包含結構化資料（Schema.org - Organization）

#### 效能要求
- **FR-032**: 首頁的首次內容繪製 (FCP) 必須 < 1.5 秒
- **FR-033**: 首頁的最大內容繪製 (LCP) 必須 < 2.5 秒
- **FR-034**: 圖片必須使用現代格式（WebP）並提供 fallback（JPEG/PNG）
- **FR-035**: 圖片必須實作 lazy loading（除首屏圖片外）
- **FR-036**: Lighthouse 效能評分必須 > 90

### Key Entities

- **Navigation Item**: 導航項目，包含名稱、連結 URL、是否為當前頁面
- **Service Card**: 服務卡片，包含服務名稱、簡短描述、圖示/圖片 URL、詳細頁面連結
- **Social Media Link**: 社群媒體連結，包含平台名稱、URL、圖示
- **Hero Content**: Hero 區塊內容，包含標語文字、背景圖片 URL、CTA 按鈕文字與連結

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者能在 3 秒內理解虎山林業的主要業務（透過使用者測試驗證，至少 80% 的受測者通過）
- **SC-002**: 首頁在標準 4G 網路環境下的載入時間 < 3 秒
- **SC-003**: Lighthouse 評分達到：效能 > 90、無障礙性 > 90、最佳實踐 > 90、SEO > 90
- **SC-004**: 網站在主流瀏覽器（Chrome、Safari、Firefox、Edge）最新兩個版本上正確顯示，無明顯排版錯誤
- **SC-005**: 網站在至少 3 種不同尺寸的裝置（手機、平板、桌機）上測試通過，無需水平捲動
- **SC-006**: 所有互動元素（按鈕、連結）的觸控目標至少 44x44px，符合 WCAG 2.1 AA 標準
- **SC-007**: 頁面色彩對比度至少 4.5:1，符合 WCAG 2.1 AA 標準
- **SC-008**: 使用鍵盤導航能訪問所有功能，焦點狀態清晰可見
- **SC-009**: 社群媒體連結點擊率 > 5%（上線後 1 個月內測量）
- **SC-010**: 首頁跳出率 < 60%（上線後 1 個月內測量）

## Assumptions *(文件化的假設)*

1. **Logo**: 假設使用專案根目錄的 `LOGO.jpg` 作為網站 Logo，後續可能需要提供不同尺寸的版本（favicon、mobile、desktop）
2. **品牌色彩**: PRD 中未指定品牌主色與輔色，假設在技術規劃階段會定義色彩系統，暫時使用自然、專業的配色（綠色系為主）
3. **Hero 背景圖**: 假設會使用虎山林業的實際工作現場照片，如暫時缺乏素材，可使用佔位符標註待替換
4. **服務卡片圖片**: 假設每項服務會有代表性圖片或圖示，如暫時缺乏，可使用 icon 代替
5. **導航項目**: 假設初期導航包含 4 個主要頁面（首頁、關於我們、服務項目、聯絡我們），未來可擴充「最新消息」等頁面
6. **多語言**: 初期僅支援繁體中文，未來如需英文版會作為獨立功能開發
7. **內容管理**: 初期內容以硬編碼方式寫入程式碼，未來如需頻繁更新，可考慮引入 CMS
8. **分析工具**: 假設會整合 Google Analytics，追蹤指標如跳出率、停留時間、社群媒體點擊率

## Out of Scope *(明確排除的範圍)*

以下功能不在本次規格範圍內，將於後續功能開發：

1. 「關於我們」頁面的詳細內容（團隊介紹、公司歷程）
2. 「服務項目」的詳細介紹頁面
3. 「聯絡我們」頁面與詢價表單
4. 部落格/最新消息功能
5. 線上預約系統
6. 客戶評價展示
7. 作品集/案例展示
8. 多語言支援（英文版）
9. 網站後台管理系統
10. 使用者註冊/登入功能

## Dependencies *(相依性)*

1. **素材資源**: 需要高品質的照片素材（Hero 背景、服務卡片圖片）

3. **網域與主機**: 需要決定網域名稱與部署平台（Vercel/Netlify/其他）
4. **分析工具**: 如需追蹤成功指標，需要設定 Google Analytics

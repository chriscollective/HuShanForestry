## Core Principles

### I. 使用者優先 (User-First)
網站的所有功能與設計必須以使用者體驗為核心考量。每個頁面、每個互動都應該清晰、直覺且易於使用。

**規範**：
- 首頁必須在 3 秒內讓訪客理解公司業務
- 所有資訊必須在 3 次點擊內可達
- 必須支援響應式設計（RWD），確保在手機、平板、桌機都有良好體驗
- 頁面載入時間必須 < 3 秒

**理由**：虎山林業的目標客戶可能在現場使用行動裝置查看，必須確保跨裝置的流暢體驗。

### II. 內容真實性 (Content Authenticity)
所有展示的內容、照片、案例必須來自虎山林業的真實工作與服務，不使用不相關的庫存圖片。

**規範**：
- 優先使用公司實際工作現場照片
- 團隊介紹必須使用真實成員資訊
- 案例展示必須來自實際完成的專案
- 如需暫時使用替代素材，必須標註並列入後續替換清單

**理由**：林業是專業且需要信任的產業，真實的內容能建立客戶信心。

### III. 效能優化 (Performance Optimization - NON-NEGOTIABLE)
網站效能是不可妥協的要求，必須確保快速載入與流暢互動。

**規範**：
- Lighthouse 評分必須 > 90
- 圖片必須經過壓縮與優化
- 必須使用現代化的圖片格式（WebP 等）
- 必須實作 lazy loading
- 首次內容繪製 (FCP) < 1.5 秒
- 最大內容繪製 (LCP) < 2.5 秒

**理由**：許多潛在客戶可能在山區或偏遠地區使用行動網路，網站必須在低頻寬環境下也能快速載入。

### IV. SEO 與可發現性 (SEO & Discoverability)
網站必須容易被搜尋引擎發現，提升虎山林業在台灣林業服務搜尋中的排名。

**規範**：
- 每個頁面必須有適當的 meta tags（title, description, keywords）
- 必須使用語義化 HTML 標籤
- 必須包含結構化資料（Schema.org）
- URL 必須清晰且具描述性
- 必須提供 sitemap.xml 和 robots.txt
- 圖片必須包含 alt 文字

**理由**：大部分新客戶會透過 Google 搜尋找到林業服務提供商，良好的 SEO 能帶來更多商機。

### V. 無障礙設計 (Accessibility)
網站必須符合無障礙標準，確保所有人都能平等使用。

**規範**：
- 必須符合 WCAG 2.1 AA 標準
- 必須支援鍵盤導航
- 必須有適當的色彩對比度（至少 4.5:1）
- 表單必須有清楚的標籤與錯誤提示
- 必須支援螢幕閱讀器

**理由**：無障礙設計不僅是社會責任，也能提升整體使用者體驗與 SEO 排名。

## 技術標準 (Technical Standards)

**前端框架選擇**：
- 優先考慮：Next.js（React）或 Astro（靜態網站生成）
- 樣式：Tailwind CSS（提供一致性與維護性）
- 型別安全：TypeScript（減少錯誤，提升程式碼品質）

**安全性要求**：
- 必須使用 HTTPS 加密
- 表單必須包含防機器人驗證（reCAPTCHA v3）
- 必須遵守個資保護法規（GDPR/PDPA 準則）
- 不得在前端暴露敏感資訊（API keys 等）

**瀏覽器支援**：
- 必須支援主流瀏覽器最新兩個版本（Chrome, Safari, Firefox, Edge）
- 必須在舊版瀏覽器提供降級體驗或友善提示

## 開發流程 (Development Workflow)

**版本控制**：
- 使用 Git 進行版本控制
- 每個功能使用獨立分支開發
- Commit 訊息使用中文，清楚描述變更內容
- 遵循 Spec-Kit 的規範驅動開發流程

**品質檢查**：
- 每次部署前必須通過以下檢查：
  - ✅ Lighthouse 評分 > 90
  - ✅ 無 TypeScript 編譯錯誤
  - ✅ 無 ESLint 警告（critical 等級）
  - ✅ 手動測試核心使用者流程
  - ✅ 跨裝置測試（手機、平板、桌機）

**內容更新**：
- 建立簡單的內容管理機制，方便日後更新
- 新增內容時必須檢查：SEO、無障礙性、效能影響

## Governance

本憲章是虎山林業官方網站專案的最高指導原則，所有技術決策與實作都必須符合本憲章的規範。

**修訂流程**：
- 憲章修訂必須有明確理由與影響評估
- 版本號遵循語義化版本（MAJOR.MINOR.PATCH）
- 每次修訂必須更新變更記錄

**合規檢查**：
- 每個功能規格（spec）必須檢查是否符合憲章原則
- 每個技術規劃（plan）必須驗證憲章要求
- 每個部署前必須執行憲章合規檢查清單

**例外處理**：
- 如因特殊原因需要違反憲章，必須：
  1. 在規格文件中明確說明原因
  2. 評估影響範圍與風險
  3. 提出補償措施
  4. 記錄決策理由
